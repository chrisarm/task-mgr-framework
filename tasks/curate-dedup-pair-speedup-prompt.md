# Claude Code Agent Instructions

You are an autonomous coding agent implementing **curate dedup pair-centric speedup** for **task-mgr**.

## Problem Statement

`task-mgr curate dedup` takes 1–2+ hours on the live DB (3,076 active learnings). Root cause: the embedding pre-filter does single-linkage union-find at cosine `--threshold − 0.05` = 0.65, chaining 1,992 items into one giant component that gets chopped into ~285 ID-sorted chunks of 7 — each chunk a full `claude` CLI subprocess at concurrency 2 (~379 batches total). Cross-chunk pairs are never compared, and merges shift chunk boundaries, defeating the `dedup_dismissals` cache.

The fix (approved plan): the embedding path becomes **pair-centric** — generate candidate pairs at a per-profile calibrated cosine threshold (jina 0.85, measured), subtract already-dismissed pairs up front, group pairs into capped batches (≤20 items, ≤30 pairs), judge with the existing `build_pair_judgment_prompt`, and record dismissals per candidate pair. Concurrency default 4. Embeddings L2-normalized once so each pair costs one dot product. The fallback path (unembedded learnings / no embeddings / empty embed_model) keeps `build_standard_batches` + the cluster prompt byte-identical. `--pair-mode` is removed (pair-centric is the only embedding-path mode); `cluster_by_embedding_similarity` is deleted.

Expected effect: first run ≈40–80 Haiku calls instead of ~379; re-runs proportional to new pairs only (near-zero LLM calls).

These are **verified access patterns** — do NOT guess key types.
